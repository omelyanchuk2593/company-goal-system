Сейчас правильное решение — сохранить новую идею в резерве со статусом `draft`. Шестой активной целью и согласованной целью с оценкой 2★ она пока стать не может по выбранной методике.

| Место | Состояние | Занято |
|---|---|---|
| S1 | Проверка завершения (`completion_review`) | Да |
| S2 | Действующая S | Да |
| M1 | Действующая M | Да |
| M2 | Действующая M | Да |
| L1 | Действующая L | Да |
| Новая идея | Черновой резерв (`draft`) | Нет |

Заявка «готово» ещё не освобождает S1: сначала нужно решение по результату. Учёт цели на проверке как занятого места — принятое правило этой реализации, а не дословное правило автора.

В формулировке «вести CRM и проводить обучение» соединены обязанность и действие. Ведение CRM остаётся в рабочем стандарте, обучение — в плане действий. Отдельную цель оправдывает проверяемое изменение в работе команды.

Предлагаю такой черновик карточки:

| Поле | Проект |
|---|---|
| Результат | **Команда самостоятельно выполняет согласованный рабочий цикл в CRM и проходит проверку по утверждённому чек-листу.** |
| Длина формулировки | 113 символов, включая пробелы |
| Статус | `draft`, вне активного портфеля |
| Владелец | Этот руководитель; его согласие на новую формулировку ещё не зафиксировано |
| Корзина | Предварительно S; подтвердить после определения начала и дедлайна, срок — до двух календарных месяцев |
| Исходная база | Уточнить: какие операции команда сейчас не выполняет самостоятельно и какие ошибки допускает. Проверить по рабочим записям CRM до согласования критерия |
| Критерий | Уточнить состав участников, перечень операций, правила самостоятельного выполнения, допустимые ошибки и способ выбора проверяемых случаев |
| Доказательства | Результаты практической проверки по чек-листу и записи реальных операций в CRM; факт проведённого обучения сам по себе недостаточен |
| Связь с общей целью | Уточнить, какую проблему компании решает освоение CRM; ожидаемую пользу не выдавать за уже полученный эффект |
| Оценка | 2★ — оценка PM исходной версии. Новая версия требует отдельной оценки; автоматически повышать звёзды нельзя |
| Проверяющие | PM — уже участвовавший в оценке человек; Reviewer — назначить по принятому порядку |

Дальше порядок такой:

1. Закончить проверку прежней S по её исходному критерию и доказательствам. Подтверждённое достижение или зафиксированное недостижение освободит место. Закрывать её только ради новой цели нельзя.
2. Руководитель дорабатывает новую формулировку, исходную базу, срок, критерий и вклад в общую цель. Если обучение и CRM решают разные проблемы, их не нужно искусственно склеивать ради одной корзины.
3. PM сначала проверяет SMART, затем амбициозность. Оценки 1–2★ возвращают цель на доработку; проходной диапазон — 3–5★. После PM цель проходит Reviewer по принятой схеме.
4. При свободном месте S и зафиксированном согласовании перевести цель в `active`. До этого она остаётся черновиком.

Именно эти ограничения закреплены в [правилах системы](<../../skills/company-goal-system/SKILL.md>): «не делай её шестой активной целью» и «Цели с 1–2 звёздами возвращаются на доработку». Поэтому желание сразу поставить отметку «согласована» здесь не заменяет доработку и решение проверяющих.
