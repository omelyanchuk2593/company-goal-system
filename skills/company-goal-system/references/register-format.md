# Формат реестра

UTF-8 CSV с запятыми и строкой заголовков. Для текста с запятой используй кавычки.
Шаблон — `assets/goal-register.csv`. Идентификаторы целей сохраняй при обновлении.
Заголовок содержит ровно эти 16 полей; их порядок может отличаться.

| Поле | Содержание |
|---|---|
| id | Уникальный идентификатор, например G-001 |
| owner | Согласованный владелец; для черновика может быть неизвестен |
| category | Направление конструктора под стратегию компании |
| horizon | S, M или L |
| statement | Самостоятельная формулировка результата, 1–249 символов |
| start_date | Начало срока, YYYY-MM-DD |
| due_date | Дедлайн, YYYY-MM-DD |
| status | Одно из состояний ниже |
| criterion | Заранее выбранный критерий, база/план/ограничения и источник измерения |
| evidence_expected | Какие доказательства потребуются |
| evidence_actual | Что предоставлено; не означает, что агент это проверил |
| pm | Человек, уполномоченный рассматривать цель |
| reviewer | Независимый второй проверяющий, если предусмотрен политикой |
| referee | Арбитр по спору, если назначен |
| ambition | Оценка 1–5; пусто до оценки, предварительные варианты держи в карточке |
| company_link | ID общей цели или конкретное объяснение связи со стратегией |

## Состояния реализации

`draft` — идея или неполная карточка, не занимает место.
`submitted` — цель внесена в портфель и ожидает согласования.
`active` — согласована и выполняется.
`completion_review` — владелец заявил результат, идёт проверка.
`appeal` — рассматривается спор.
`achieved` — уполномоченные люди подтвердили достижение.
`failed` — зафиксировано недостижение.
`cancelled` — утверждённая отмена с причиной в журнале.

Место занимают submitted, active, completion_review, appeal. Возврат формулировки
на доработку переносит её в draft с записью причины. Окончательное закрытие
освобождает место. Названия статусов и правила учёта — операционная адаптация,
а не буквальная копия программного продукта из презентации.

Не заполняй обязательные поля словом «уточнить», чтобы пройти валидатор и
объявить цель согласованной. Неполная цель остаётся draft. Финальный статус
требует человеческого решения в журнале; CSV сам по себе его не доказывает.

Каждой строке нужны id и известный status. Для draft/cancelled остальные поля
могут быть пустыми. Для занимающих место состояний, achieved и failed нужны
owner, category, horizon, statement, обе даты, criterion, evidence_expected,
pm, company_link. Для achieved дополнительно нужен evidence_actual. Любые
указанные даты, горизонт и оценка проверяются даже в черновике.

## Ограничения проверки

Скрипт проверяет структуру и очевидные нарушения портфеля. Результат без ошибок
не означает, что цель измерима, evidence достоверен, PM действительно согласовал
её или все участники приняли политику. Первоначальный порядок открытия корзин
проверяется по истории; текущий CSV для этого недостаточен.
